# Desktop app (`@app/desktop`)

Electron 45 wrapper around the existing app. It adds no features of its own: the API (`apps/api`) and web app (`apps/web`) run unchanged, so everything they do (and every safety rule) applies here too. It imports nothing from the other workspaces; it runs their built output.

- **Main process** (`src/main.ts`, ESM): one instance (`requestSingleInstanceLock`). Starts `apps/api/dist/index.js` with `utilityProcess.fork` on `127.0.0.1:47821` (`PREFERRED_PORT`, fixed so the window's origin, and the web app's localStorage UI prefs, stay the same between launches; any free port when it's taken), waits for `GET /health`, then opens a `BrowserWindow` on `http://127.0.0.1:<port>/` (context isolation, sandbox, no Node; the preload only names the platform, see Window). Links the app opens in a new tab, and any navigation off the app's origin, go to the system browser (`shell.openExternal`). Only the app's own origin gets permissions (the microphone for voice mode). Quitting stops the server first (SIGTERM via `kill()`, which stops its MCP servers, tasks and terminals; 5 s cap). A server that exits on its own shows an error and quits. The server's stdout/stderr go to `app.getPath('logs')/server.log` (`~/Library/Logs/Nimbrio AI/server.log` on macOS).
- **Window**: on macOS no title bar (`titleBarStyle: 'hidden'`, traffic lights at x 16 / y 17, centred in the web app's 48px top bars). `src/preload.cts` (sandboxed, so CommonJS) exposes only `window.nimbrioDesktop = { platform }`; the web app's `public/theme-init.js` turns it into `data-desktop` on `<html>` before first paint, and `index.css` then sets `--titlebar-inset` (64px; 0 in a browser and while `data-fullscreen` is set, which `main.ts` toggles on entering/leaving full screen) and makes `.titlebar` bars drag the window (their buttons, links, inputs, tabs, menus and dialogs don't). The bar at the window's top-left adds the inset to its left padding: the sidebar header, the chat header while the sidebar is collapsed (xl), and `AppNav` below xl. Other platforms keep the system frame for now.
- **Server env**: the app's env plus `PORT`, `NODE_ENV=production`, `SIGN_IN=off` (no Supabase sign-in in the desktop app; Electron drops empty env values, so emptying `SUPABASE_URL` can't do it) and the login shell's PATH merged in front (`src/shell-path.ts`: `$SHELL -ilc` prints PATH between markers, 5 s timeout), because apps opened from Finder get only `/usr/bin:/bin:/usr/sbin:/sbin` and the agent's commands couldn't find node, npm or Homebrew tools.
- **Paths**: the API finds the web app and the repo `.env` relative to its own file, so the packaged app keeps the repo's layout: `apps/api/dist`, `apps/web/dist`, `apps/desktop/dist` and `node_modules/@app/{shared,agent,db}`. From a checkout (`npm run desktop`) the same relative paths point into the repo (and its `.env` is read, but `SIGN_IN=off` wins); packaged, there's no `.env`.
- **Packaging**: `npm run desktop:dist` (root) = root build, `tsc`, `scripts/stage.ts`, `electron-builder` (`electron-builder.yml`). `stage.ts` fills `.stage/` (git-ignored): a `package.json` whose dependencies are the third-party runtime dependencies of api/agent/db/shared pinned to the versions installed in the repo, `npm install --omit=dev`, then the built output and the internal packages copied in, and only then the `@app/*` names added to the dependencies (electron-builder packs only listed ones; listing them before the install would make npm look them up on the public registry). It also sets node-pty's `spawn-helper` executable, since npm drops the bit and the API's runtime fix can't change files inside the signed app. electron-builder packs `.stage` into `release/` (git-ignored): `app.asar` with node-pty unpacked, no native rebuild (node-pty ships Node-API prebuilds for macOS and Windows; Linux would need one), mac `dmg` ad-hoc signed (`identity: '-'`, `hardenedRuntime: false`; Apple silicon refuses unsigned apps, and a downloaded copy needs Privacy & Security → Open Anyway until a Developer ID and notarization are set up), Windows `nsis`. It builds for the machine it runs on; electron-builder downloads Electron and its tools from GitHub, which sometimes answers 504, so retry.
- **Not in the desktop app**: voice input (Chrome's speech recognition sends audio to Google's speech service, which Electron doesn't include; spoken replies still work), Install app (no `beforeinstallprompt`), auto-update.
- **Tests**: `test/shell-path.test.ts` (offline). The packaged app was checked by hand: health, the web app from `app.asar`, sign-in off, and a terminal session (node-pty from `app.asar.unpacked`) finding node on PATH.
